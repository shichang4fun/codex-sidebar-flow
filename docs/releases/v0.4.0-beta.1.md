# v0.4.0-beta.1 — Local event-driven Desktop proxy

This opt-in macOS prerelease organizes eligible local Codex tasks using structured
App Server events and native Desktop tools. The new path requires no sorting model
turns, lifecycle Hooks or heartbeat.

## Install

Follow the [versioned installation and rollback guide](https://github.com/shichang4fun/codex-sidebar-flow/blob/v0.4.0-beta.1/docs/local-desktop-proxy.md).
Use the dedicated **Codex Sidebar Flow.app** or command entry every time you start
Codex; the original app icon bypasses this integration. Plugin enablement and
`scripts/setup.mjs` still select the separate legacy Hook path, not this proxy.
Disable legacy writers before migration; this release does not silently change
existing installations or automations.

## Included

- Active tasks move to In Progress; confirmed completion/attention moves to For Review.
- Explicit local-only scope, exclusions, allowlist and hot disable.
- Protection for Pinned, For Later, Projects, remote, archived and ambiguous tasks.
- Content-hashed runtime snapshots, attachment diagnostics and recoverable uninstall.
- Independent review fixes for newly assigned Project membership and final server
  responses being lost on client EOF, with regression tests.

## Verification and limits

- 151 automated tests passed locally; 3 opt-in real App Server integration tests
  passed separately using an isolated home and loopback fake model.
- Start/completion movement was observed on two real local Desktop tasks on
  bundled Codex CLI 0.153.4 before the final review hardening. The review fixes
  have automated regression and isolated protocol evidence, not a new full
  Desktop lifecycle acceptance run.
- Third-task discovery, repeated normal launch through the installed entry, and
  real approval/cancellation UI acceptance remain open acceptance items.
- Remote and Project tasks are unsupported by the new path. There is no periodic
  repair, atomic read/move guarantee, guaranteed event delivery or latency SLA.
- The launcher is unsigned and the integration is Desktop-build-specific. Retest
  after Desktop updates. No new TCP listener or telemetry is installed; the trusted
  proxy necessarily sees the original App Server stream.

This is a **prerelease**, not the stable Latest release. No npm package is published.
